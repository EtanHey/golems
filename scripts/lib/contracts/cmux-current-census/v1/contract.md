## Structural and lexical contract

Use JSON Schema draft 2020-12 for shape. Each object's required list selects mandatory properties; no extra members. The newly added kernel_identity_observation is optional at process/attempt/registration evidence locations; prior complete-or-unavailable observations need no invented partial record. All arrays have a resource ceiling. All opaque record identifiers are bounded lowercase identifiers. Collection/observation times and kernel start fields are canonical nonnegative decimal strings without leading zeroes; microseconds are 0–999999. PID/PPID/UID use safe bounded integers. Kernel start seconds and microseconds remain separate. Launch identity is exactly host+OS-boot+PID+start-seconds+start-microseconds; UID and cwd have separate authoritative evidence.

Reject duplicate JSON keys before ordinary parsing, invalid Unicode (including lone surrogates), nonfinite numbers, invalid UTF-8 and oversized input. Reject unknown members. Duplicate keys differ from duplicate record IDs, duplicate final identities or legitimate repeated observations. Schema validation alone cannot perform all lexical/cross-reference/evidence checks described here.

All null values outside `missing_evidence` MUST have exactly one matching entry there. `field_path` is an absolute RFC6901 JSON Pointer, using canonical decimal array indexes; it must resolve to that null value. No dangling, duplicate, nonnull-target or ancestor-only reasons. Expected nulls use NOT_APPLICABLE; unavailable/unreadable/unmapped/unknown/uncaptured evidence uses its corresponding reason code. Ordinary-shell null sessions are valid only with explicit ORDINARY_SHELL classification and NOT_APPLICABLE reason. Unknown agents cannot be reclassified to waive session/launch evidence.

`members:null` means unavailable full membership. `members:[]` means an authoritative observed empty full set. A missing-evidence sidecar cannot legalize unobserved `[]`. `observed_members` is always a nonnull array containing retained partial/positive observations, not an absence attestation; an empty observed-members array says only that no positive observations were retained. Authoritative members must include all retained observations for that particular observation. A changed/churning or failed full inventory is not authoritative even if its partial rows look plausible.

## References, provenance and membership

When full launch identity is unavailable but any kernel components were obtained, retain kernel_identity_observation on the relevant process, attempt and/or registration evidence record. Its host_id, os_boot_id, pid, start_seconds, start_microseconds and uid are individually nullable with exact missing_evidence pointers; provenance is required. At least one kernel component (PID, UID or either start component) must be known. Omit this optional object only when no partial observation exists; do not discard available fields merely because complete launch is null. Component types match their full-identity counterparts. This object preserves observations, not a launch reference. Known components must agree with corresponding process/attempt fields and any complete tuple recorded beside them; incompatible components remain explicit unresolved evidence.

Partial identity cannot satisfy VERIFIED process binding, VERIFIED_CURRENT registration joins, final authoritative launch membership, historical_binding_known or path release. Shape constraints require nonnull strict complete launch/captured_launch for verified records; contextual final/historical/path exclusions remain normative and are not executed by a semantic validator here. If host/boot is unknown, complete launch remains null, binding remains unresolved and the census remains INCOMPLETE even when PID and both kernel start components are known. Fixture 16 preserves that evidence at all three locations. It supplies no guessed harness join or path-release proof.

All attempt, membership-observation, resolution, surface-record, process-record and registration-record IDs are unique in one envelope namespace. References resolve within this envelope to the specified record kind. Array reference sets are unique; forward references are permitted. Blocker subjects may reference any record. Provenance source_component must identify an entry in source_versions; unknown/unavailable source_versions remains INCOMPLETE. Provenance records state source, method and time; they do not by themselves prove truth. Native hints/fallback directories cannot satisfy kernel-cwd or harness-launch requirements. Nonnull observation times must lie within their attempt/collection intervals; round-two reads follow the failed round-one attempt. Launch host/boot must match this envelope, PID must match its process/failed-attempt subject, and process UID must match owner_uid; an unknown/mismatched value blocks required binding.

Process records are observations: repeated launch tuples may occur under distinct process-record IDs/attempts. `coverage.process_observation_refs` identifies their retained union, and MUST include every process record exactly once. `final_process_refs` identifies only reconciled final scoped membership; its launch tuples and PIDs are unique and match the final authoritative owner membership. A final process needs known launch/UID/kernel cwd; a missing one prevents authoritative final membership. `final_surface_refs` and `final_registration_refs` similarly designate final inventory, distinct from retained observations. Final surface diagnostic IDs and mapped surface IDs must be unique and match native inventories, including unmapped objects. Partial record arrays retain available observations; unknown final inventories are null, not partial arrays. Required coverage includes before/after tree and independent WINDOW/WORKSPACE/PANE/SURFACE sets, diagnostic TERMINAL sets, and owner PID/launch sets; missing/unmatched scope remains INCOMPLETE. All raw rows remain in registration_dispositions even if unreadable/malformed/old; do not discard historical1834 or use age/EPERM/empty bindings to waive protection.

Raw registration identity is `(registry_id,row_number)`; row_number is one-based, byte_offset is corroborating telemetry. Duplicate raw row identities fail, even under different record IDs. An unreadable row retains its reference with null digest/launch/path evidence and reasons. Verified joins require the actual harness process, identical kernel launch tuple and authoritative witness provenance. Registration time, parent PID telemetry, surface ID or cwd similarity cannot join. OLD_BINDING_DISPROVED settles only that old binding; it does not release unknown paths. Surfaces with unknown lifecycle or unmapped diagnostics remain blockers.

## ESRCH resolution acceptance

A resolution points to one retained ESRCH attempt. UNRESOLVED grants no absence proof. Reconciled dispositions require round-two fresh authoritative OWNER_LAUNCH membership, successful identity rereads covering every surviving/new/reused final process, and native rereads of tree plus independent WINDOW/WORKSPACE/PANE/SURFACE membership, diagnostic TERMINAL membership and current surface bindings. These references must describe the same rebracket interval and agree with final inventories; hints cannot replace them.

The failed PID must be absent for DISAPPEARANCE_RECONCILED. PID_REUSE_RECONCILED requires a previously captured old launch and independently captured replacement at the same PID with different start identity, explicitly included in replacement_process_refs and final membership. Every survivor/replacement reference resolves; together they account for final owner launches without omission. Missing prior launch means historical_launch is null and historical_binding_known is false. A resolution cannot reconstruct historical identity/path from fresh absence. Known historical launch must equal the failed attempt's captured tuple; historical_binding_known does not prove a worktree path. Keep failure and resolution; unrelated EPERM, unknown cwd, legacy paths and unmapped terminals remain blockers.
